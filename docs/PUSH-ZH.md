# Clio 手机访问与消息推送

“手机能打开 Clio”和“Clio 能主动给手机发通知”是两件不同的事。

## 一、手机能做什么

只要 Clio 已经运行在电脑或 VPS 上，并且手机能安全访问它的管理地址：

| 功能 | iPhone / iPad | 安卓手机 / 平板 |
|---|---:|---:|
| 浏览器打开管理小屋 | 支持 | 支持 |
| 搜索、查看、修改和导出记忆 | 支持 | 支持 |
| 查看信箱、日历、未竟和状态 | 支持 | 支持 |
| 通过兼容客户端连接 MCP | 取决于客户端 | 取决于客户端 |
| 接收当前内置 Bark 主动通知 | 支持 | 不支持 |

手机本身通常不承载 Clio 服务器。电脑关机、VPS 停止或网络入口失效时，手机页面也会暂时无法访问。

## 二、当前为什么只有苹果主动推送

Clio 当前内置的是 Bark 通道。Bark 是面向 iPhone 和 iPad 的通知工具，所以：

- iPhone/iPad：配置自己的 Bark Device Key 后，可以接收主动通知。
- 安卓：记忆管理、网页和 MCP 不受影响，但不会从 Bark 收到系统通知。
- 不配置 Bark：Clio 的记忆、检索、信箱和状态功能仍能使用。

通知顶部的名字可以在管理小屋的“设置 → 推送署名”中修改。保存后会一直使用这个名字，刷新页面、换窗口或重启容器都不会恢复默认值；下一次手动修改后，后续通知才会换成新名字。

## 三、安卓以后怎么接

推荐把推送层做成可切换的“邮差”：

- `bark`：保留现有苹果推送。
- `ntfy`：可用于苹果和安卓。
- `off`：完全关闭主动推送。

状态、暗涌和行为判断仍由 Clio 完成，只替换最后负责送达消息的通道。这样不会复制记忆，也不需要为安卓重做一套状态系统。

当前公开版本尚未实现 `ntfy`，因此安装说明不会把安卓主动推送写成已经可用。增加新推送通道时，应单独完成配置、去重、静默时段和真实手机验收。

## 四、隐私提醒

- Bark Device Key、ntfy Token 或其他推送凭据都只能放在 `.env` 或私人配置中。
- 不要把完整推送地址放进截图、README、日志或 GitHub。
- 推送正文会经过所选推送服务。不要把不希望第三方通道处理的敏感原文直接作为通知发送。
- 公网管理页应使用 HTTPS、强密码和访问控制，不要把容器端口直接暴露在公网。
